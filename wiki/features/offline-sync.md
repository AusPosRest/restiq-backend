# Offline sync for the Windows hub till - backend

Design: Restiq `docs/SYNC-DESIGN.md` (accepted 2026-10-07). Issue restiq-backend#185.

## Capabilities

- **D15** Offline-first selling - one hub till per outlet sells offline and catches the cloud up; the cloud owns menu, prices, staff and floor plan, the hub owns sales.

## What's built

- **Device key at enrolment** - `POST /device/v1/enroll` takes optional `publicKey` (base64 SPKI DER, ed25519), checked before the code is used up - `src/ops/devices/devices.service.ts`.
- **Device realm** - `/sync/v1/*` is signed, not token-authenticated: headers `X-Device-Id`, `X-Device-Timestamp` (ms), `X-Device-Signature` (base64 ed25519 over `METHOD\npath?query\ntimestamp\nsha256hex(raw body)`), 5-minute skew. 401 `invalid_signature` for any failure, 403 `device_revoked` / `device_not_in_outlet` / `tenant_inactive` - `src/platform/device-sync.guard.ts`, `device-signature.ts`. `main.ts` keeps the raw body for this.
- **Change feed** - `sync_changes` (bigserial id = cursor), written by the `sync_record_change()` trigger on the 21 cloud-owned tables - migrations `20261113180000_offline_sync`, `20261113200000_sync_tenant_brand_feed` (adds `tenants` and `brands`, #292). Pruned daily to 30 days (`SyncService.prune`, skipped when `RESTIQ_HUB=1` or in tests); each tenant's newest change is always kept.
- **Hub only** (#292) - `bootstrap` and `push` answer 403 `not_hub` unless the device's `role` is `hub` (ops designates it). Pull, session status, heartbeat and rejections stay open to any keyed device in the outlet.
- `GET /sync/v1/bootstrap` - every cloud-owned row (including the caller's own `tenants` row and its `brands`) for the device's tenant and outlet as plain rows (database column names), the role permission catalogue, `policy` (`maxOfflineHours` from `tenants.max_offline_hours`, default 24; `syncIntervalSeconds` 30) and a cursor - `src/pos/sync/sync.service.ts`.
- `GET /sync/v1/bootstrap?include=open_sales` (#301, B6, hub only) - the same payload plus `openSales`: the outlet's orders that are not `closed`, plus any order with a `queued` ticket (paid but still cooking, so the hub's kitchen has its lines), with their lines (combo children included) and line modifiers, `open` bills with their tenders, `queued` tickets with their ticket lines, the open shift with its cash movements, and the outlet's `token_number_counters` row. Table list `OPEN_SALES_TABLES` (exported from `src/pos`). These tables are hub-owned, so they are not in `CLOUD_TABLES` or the change feed; they are for a hub's re-bootstrap (replacement, `cursor_expired`, coming back after a cloud fallback - D-3). Without the parameter bootstrap is unchanged.
- `PUT /sync/v1/hub-address` `{ urls }` (#301, B4, hub only, 204) - 1 to 4 LAN base URLs, each `http(s)://` + a private IPv4 (10/8, 172.16/12, 192.168/16) or `*.local` host + an explicit port, no path (`isLanUrl` in `sync.dtos.ts`); anything else 400 `validation_failed`. Stored in `devices.lan_urls` / `lan_announced_at` (migration `20261114100000_device_lan_urls`).
- `GET /sync/v1/hub` (#301, B4, any keyed device) - `{ deviceId, urls, announcedAt }` of the caller's outlet's active hub; 404 `no_hub` when there is none or it never announced. Replaces the design's `/device/v1/hub` (thin clients are enrolled with keys). Plain HTTP on the shop LAN (D-4).
- `GET /sync/v1/pull?cursor=&limit=` - rows changed after the cursor, latest per row, read as they are now (`delete` when gone). A cursor above 0 but below the tenant's oldest kept change answers 410 `cursor_expired`: bootstrap again.
- `POST /sync/v1/heartbeat` (#292) - `{outboxDepth, appVersion, clockSkewSeconds, recentRejectionCount}` (same DTO and same device columns as the ops heartbeat, via `heartbeatData()`), 204; `GET /ops/v1/sync-health` shows the values.
- `POST /sync/v1/push` - see below - `src/pos/sync/sync-push.service.ts`.
- `GET /sync/v1/session-status` (with `isHub`), `GET /sync/v1/rejections`, `POST /sync/v1/rejections/:opId/acknowledge`.

### Push

Body `{batchId, ops[1..200]}` (201+ → 413 `batch_too_large`). Each op `{opId, seq, type, at, actorStaffId, payload}`. Result per op: `accepted`, `duplicate` (opId already in the AD-7 `applied_ops` ledger), `rejected` (with `code`, kept in `sync_dead_letters`), or `deferred` (`seq_gap`: seq is not `lastAppliedSeq + 1`, so this op and the rest wait for the missing one).

| type | payload | online equivalent |
|---|---|---|
| `order.create` | `orderId`, and `tableId` or `tokenNumber` (counter order keeps the hub's token) | open table / counter order |
| `order.line.add` | `orderId`, `lineId`, `itemId`, `variantId?`, `quantity`, `modifierIds?`, `seatNumber?`, `note?`, `unitPriceMinor` (string), `modifierPriceMinor?` (`{modifierId: string}`) | add line - at the hub's price, not today's |
| `order.line.update` | `orderId`, `lineId`, plus the update fields | update line |
| `order.line.remove` | `orderId`, `lineId` | remove line |
| `order.status` | `orderId`, `status` | status change (fires kitchen tickets on `sent`) |
| `bill.create` | `orderId`, `billId` | create bill |
| `bill.finalize` | `billId`, `tenders`, `tenderIds` (one per tender), `discountMinor?`, `discountReason?` | finalize |
| `order.combo.add` (#297) | `orderId`, `lineId` (parent), `comboId`, `quantity`, `unitPriceMinor`, `seatNumber?`, `children[]` of `{lineId, itemId, variantId?, quantity (whole line), unitPriceMinor, modifierPriceMinor?}` | add combo - the hub's lines and prices as written; slots and availability are not re-checked |
| `order.line.void` (#297) | `orderId`, `lineId`, `reason`, `approvedByStaffId` | void after fire - no PIN; audited `sync.void_approved_offline` with the approver |
| `order.transfer` (#297) | `orderId`, `newOwnerStaffId`, `reason?` | transfer |
| `order.discard` (#297) | `orderId` | discard empty order |
| `shift.open` (#297) | `shiftId`, `outletId` (must be the hub's), `floatMinor` | open shift |
| `shift.cash_movement` (#297) | `shiftId`, `movementId`, `type`, `amountMinor`, `reason` | paid out / bank drop |
| `shift.close` (#297) | `shiftId`, `countedMinor` | blind close |
| `clock.in` (#297) | `clockEventId` | clock-in written at PIN login (skipped if the cloud already has one that local day) |
| `clock.out` (#297) | `clockEventId` | clock out - kept even if the cloud never saw the clock-in |
| `ticket.bump` (#297) | `orderId`, `stationId` (uuid or `null` = unrouted) | bump the order's queued ticket at that station |
| `ticket.recall` (#297) | `orderId`, `stationId` (uuid or `null`) | recall the ticket there bumped last; the 12 h window is not re-checked |

Ids made on the hub are kept, and `at` becomes the row's business time (`createdAt`, `finalizedAt`, `voidedAt`, `openedAt`/`closedAt`, `occurredAt`, `bumpedAt`/`recalledAt`). Clock ops need no permission; shift ops need `settle_bills`, ticket ops `fire_kitchen`, the rest `take_orders`. Refunds stay cloud-only (D-1) and ticket refire stays on the hub - neither is an op. The payload classes are exported from `src/pos` (`Sync*Payload`) so the hub's op recorder validates against the same rules.

## Integration points for later stories

- Desktop hub (restiq-desktop): bootstrap into its local store, outbox → push, pull every `syncIntervalSeconds`, lock when `mustSyncBefore` passes.
- Per-device bill number series waits on decision O5; bills are still numbered by the cloud at finalize.
- Ops dead-letter replay of sync ops (payload is not stored, by NFR-15).

## Key decisions

- **Device realm, key at enrolment.** The one-time enrolment code is the trust anchor, so the key rides on it; no separate key endpoint, no staff token for sync. Each op names its staff member.
- **Money ops are never refused for a lapsed permission (S3).** The sale happened; it is applied and an `sync.permission_lapsed` audit event is written. A large discount approved on the hub is applied with a `sync.discount_approved_offline` audit event - a manager PIN never travels in the outbox.
- **A replayed cash settle skips the open-shift check** that online cash needs (#208): the hub already took the cash.
- **Tickets by order + station (#297).** The cloud makes its own ticket ids in `fireOnSend`, so the hub names the order and station. `fireOnSend` keeps at most one queued ticket per order and station, so a bump means that one and a recall the one bumped last; none in that state means a re-send already applied (no-op), no ticket at all is rejected `not_found`.
- **Re-sends are safe.** Ledger first; if the ledger write was lost after an apply, the re-sent create hits the hub's own id (unique violation → accepted), a status already reached is a no-op, an already finalized bill is accepted; likewise an already voided line, a discarded order (its `order.discarded` audit exists), a closed shift, a bumped/recalled ticket.
- **Settle window.** Pull only shows changes older than 30 s, so a slower transaction that took a lower id is not skipped; a transaction longer than that could still be missed (upgrade path: commit-ordered feed).
- **No FK from `sync_changes` to `tenants`** - an append-only log read by tenant; an FK would make every tenant hard-delete clear it first.
- Pull and bootstrap filter by tenant explicitly on top of RLS, as the rest of the codebase does.
- **`cursor_expired` without a watermark (#292).** A hub's cursor is always one of its own tenant's change ids (or 0), so "below the oldest kept id" means changes it never saw were pruned. Keeping each tenant's newest change stops a quiet tenant's caught-up hub from reading as expired.

## Hub mode (issue #293)

The hub till runs this backend's own POS and kitchen code on an in-process PGlite store (Postgres in WebAssembly) - HUB-BUILD-PLAN H1/H7.

- **Entry** `src/hub/hub-main.ts`. Env: `HUB_DATA_DIR` (PGlite data dir, required), `HUB_PORT` (default 8180), `POS_JWT_SECRET` (required; the hub's own, so a hub token is never valid in the cloud). Listens on `127.0.0.1` only, no CORS. `STRIPE_SECRET_KEY` is cleared, so any Stripe path answers 503 `payments_not_configured`.
- **Store** `src/hub/store.ts`: opens PGlite, applies each `prisma/migrations/*/migration.sql` not yet in `hub_migrations` (one transaction each, so a restart applies only new ones), grants the `restiq_app` role every table and sequence, then `SET ROLE restiq_app` on the one connection Prisma uses (`pglite-prisma-adapter`) - PGlite's own user is a superuser and would bypass RLS. `setPrismaClient()` in `src/db/client.ts` installs that client before Nest boots.
- **Module** `src/hub/hub.module.ts`: `PlatformModule` + `KitchenModule` + the POS controllers and services listed directly - not `PosModule`, so `OpsModule`, `GuestModule`, sync, admin and webhook controllers and the sync-health sweep timer are never created. `GuestSessionsService`, `GuestBillsService`, `GuestCardPaymentsService` and `CardReadersService` are provided only because POS services inject them.
- **Allowlist** `src/hub/allowlist.ts`: method + path list of what the POS and KDS screens call (plan §1) plus `GET /health`; anything else answers 404 `{ error: { code: 'not_on_hub' } }`.
- **Artifact** `pnpm build:hub` → `dist-hub/{hub.cjs, migrations/, package.json, node_modules/}`: `nest build` (decorator metadata) then esbuild bundles `dist/hub/hub-main.js`; `argon2` and `@electric-sql/pglite` stay external and are `npm install`ed next to it. Run with `node dist-hub/hub.cjs`. About 41 MB on disk (hub.cjs 14 MB, PGlite 25 MB, argon2 1 MB), 12 MB gzipped.
- **Checks**: `src/hub/hub.spec.ts` (in-memory PGlite, in `pnpm test`): every migration applies once, PIN login + `GET /pos/v1/menu`, 404 off the allowlist, RLS under the app role. `pnpm smoke:hub` boots the built artifact on a temp dir; CI job `hub-smoke` runs it on ubuntu and windows-latest and uploads `restiq-hub` from main.
- **Sync state** `src/hub/meta.ts` (#296, H2): hub-only `hub_meta` table (one row), created by the store after migrations: tenant, outlet, device (set by the sync worker), pull cursor, policy, permissions, `last_sync_at`, `must_sync_before` (last sync + `maxOfflineHours`), `locked`, `lock_reason`. `readMeta()` returns it, or undefined before the first bootstrap.
- **Import** `src/hub/import.ts` (#296, H2): `importBootstrap(pg, payload, dataDir)` and `applyPull(pg, page)` take the cloud's own `SyncService` return shapes; no network here. Each runs in one PGlite transaction with `SET LOCAL ROLE NONE` (superuser) and `SET LOCAL session_replication_role = replica` (FK and `sync_record_change` triggers off), so the connection is back on `restiq_app` when it ends, error or not; PGlite runs every query under one lock, so no Prisma query can slip in. Rows go in with `INSERT … SELECT * FROM jsonb_populate_recordset(null::"<table>", $1) ON CONFLICT (id) DO UPDATE` over `CLOUD_TABLES` only - entity names from the payload pick a table from that list, never reach SQL. Bootstrap is a snapshot: rows of those tables missing from it are deleted, then everything is upserted and `hub_meta` written; the payload is then saved as `HUB_DATA_DIR/bootstrap.json` (temp file + fsync + rename) for recovery (H5). Pull applies upserts and deletes in version order, skips tables this hub doesn't know, and saves `nextCursor` in the same transaction.
- **UTC session** (#296): the store sets `TimeZone = 'UTC'` on open. PGlite otherwise takes the host's whole-hour offset (`Etc/GMT-5` on an IST machine), and the `20261011093000_database_timezone_utc` migration only reaches sessions opened after it - so on the first run Prisma's UTC wall-clock times were read hours off and an imported price was not yet "effective" on the hub menu.
- **Checks**: `src/hub/import.spec.ts` (in-memory PGlite, `pnpm test`): import, `hub_meta`, `bootstrap.json`, pull order/delete/cursor, idempotent re-import, rollback on a bad row keeps the app role. `test/hub-import.e2e-spec.ts`: the cloud's real `SyncService.bootstrap` imported into PGlite with every table's rows equal, a cloud price change and a delete pulled and shown by the hub's `GET /pos/v1/menu`, re-import idempotent.
- **Op recorder** (#300, H3): every hub write becomes a sync op before the till hears it worked. `src/hub/op-recorder.interceptor.ts` (global, hub app only, installed by `createHubApp(pg, dataDir)`) runs all non-GET requests one at a time under one mutex: handler -> build the op -> append to `HUB_DATA_DIR/outbox.log` and `fsync` -> insert into `hub_outbox` -> reply. `at` is when the handler started, `opId` a UUIDv7, `seq` max + 1 (starts at 1, no gaps), `actorStaffId` the signed-in staff (the login routes use the staff in the response).
  - `src/hub/op-map.ts`: method + path -> op builder from request body, params, response and `request.staff`. Ids the hub made come from the response (new order/line/combo children by `createdAt` >= handler start, modifier prices, tender ids matched by method + amount, shift/movement/clock ids, ticket order + station); the void's approving manager from the `void_after_fire` audit row. Payloads are built field by field, so `managerPin` never travels. A route that only returns an existing row (re-opening a busy table, a second bill request) records nothing.
  - Routes: login/select-outlet -> `clock.in` (only when the login wrote one); table order/counter order -> `order.create`; lines -> `order.line.add`; PATCH line -> `order.line.update` (with `modifierIds`, also `modifierPriceMinor` - the hub's prices, which the cloud's replay keeps, like `order.line.add`); DELETE line -> `order.line.remove`; void -> `order.line.void`; combos -> `order.combo.add`; status -> `order.status`; transfer -> `order.transfer`; DELETE order -> `order.discard`; bill -> `bill.create`; finalize -> `bill.finalize`; shifts open/cash-movements/close -> `shift.*`; clock out -> `clock.out`; ticket bump/recall -> `ticket.bump`/`ticket.recall`. Local only (no op): logout, print, print-job printed, close-session, heartbeat, ticket refire. Refunds and card payment intents answer 409 `offline_unsupported` before the handler runs; so does any write route missing from the map (fail closed).
  - If building an op throws after the handler committed, it is logged (`NO SYNC OP`) and nothing is recorded; H5 reconciles such orphans. A journal or outbox failure fails the request.
  - `src/hub/outbox.ts`: hub-only `hub_outbox` (seq, op_id, type, at, actor_staff_id, payload, acked_at, result), created by the store after migrations. `src/hub/journal.ts`: `appendOp` (append + fsync), `readJournal` (skips a torn last line only), `writeAck`/`readAck` for the `outbox.ack` watermark (temp + fsync + rename, the sync worker writes it), `compactJournal` (startup only, empties the log when the ack covers its last seq).
  - **Manager PIN on the hub**: `OrderLinesService.voidLine` now checks the PIN before opening its transaction - inside it, `ManagerAuthService.authorize`'s own queries waited on the hub's single PGlite connection until the transaction timed out (5 s, 500). `BillsService.finalize` does the same for a discount with a PIN: it verifies the PIN before its transaction and uses the result only if the discount turns out to be above the threshold (same codes and order as before; a PIN sent with an under-threshold discount now counts against the manager-PIN limiter even though it isn't needed). `refund` still verifies inside its transaction, but refunds are refused on the hub. Every hub write route was checked: the others open one transaction and make no outside query inside it (`op-recorder.spec` runs them all, local-only ones included).
- **Checks** (#300): `src/hub/op-recorder.spec.ts` (PGlite, `pnpm test`): the op map covers exactly the allowlist's write routes; a whole sale through the hub's HTTP API records 24 ops of all 18 types in seq order (including a 30% discount approved by manager PIN after a wrong-PIN 401 that records nothing, and a line update adding a modifier), equal in outbox and journal, no PIN in the log; every payload passes its `Sync*Payload` class; the journal holds each op when the reply is sent; refund and card intent 409 `offline_unsupported` with nothing recorded; journal compaction and torn-line handling. `test/hub-op-recorder.e2e-spec.ts`: bootstrap from the cloud, the same sale on the hub, ops pushed through the cloud's `SyncPushService` all `accepted` after the cloud's modifier price changed (pushed lines keep the hub's price), and cloud bill (number, subtotal, tax, round-off, status), tenders, order lines with modifiers and the shift equal the hub's.
- **Sync worker** (#304, H4): `src/hub/sync-worker.ts` + `src/hub/signer.ts` (ed25519 over the backend's own `signingString`; X-Device-* headers on every call, path signed as the cloud sees it). One tick every `policy.syncIntervalSeconds` (15 s until the cloud says otherwise) and right after each recorded write (`createHubApp(pg, dataDir, onOp)` kicks it); ticks never overlap, and kicks during a tick queue one more.
  - Tick: `GET session-status` (stores the policy) -> no `hub_meta` yet: `GET bootstrap?include=open_sales` + `importBootstrap` (sets `hub_meta.device_id`) -> push the unacked outbox in seq order, batches of 200 (`accepted`/`duplicate`/`rejected` -> `acked_at` + `result`, rejected also into `hub_rejections`; the first `deferred` stops the push, keeps it and every later op, and shows in `worker.blockedAt` `{seq, code}`; `outbox.ack` moves to the highest answered seq - the cloud applies seq strictly in order) -> pull until `hasMore = false` through `applyPull` (only `CLOUD_TABLES`, so hub-owned sales are never overwritten) -> replace `hub_rejections` with `GET rejections` -> `POST heartbeat {outboxDepth, appVersion, clockSkewSeconds, recentRejectionCount}`.
  - 410 `cursor_expired` -> bootstrap again: with `include=open_sales` only while the outbox is empty, else reference data only. `importBootstrap` now loads `openSales` when present (upserts; the hub's other sales stay). The cloud makes its own ids for line modifiers, tickets and the token counter, so the hub's copies under the imported orders/lines (and the outlet's counter) are dropped first - nothing counted twice.
  - Any failure: `online = false`, backoff 1 s, 2 s, 4 s ... 60 s (`backoffMs`), then the interval again once a tick works. 401 `clock_skew` stores the cloud's `serverTime` offset as `clockSkewSeconds` (also taken from push/pull `serverTime`). 403 `device_revoked` (from any call): `locked = true`, `lock_reason = 'revoked'`, every `staff_users.pin_hash` cleared, worker stops for good (also on the next start); the outbox and journal stay for ops to recover.
  - State for H5/H6: `hub_meta.online`, `clock_skew_seconds` (new columns), `last_sync_at` (= last successful pull), `must_sync_before`, `locked`/`lock_reason`; hub-only `hub_rejections (op_id, type, code, message, at, acknowledged)` from `createOutboxTable`; `worker.status()` adds `outboxDepth`, `lastError` and `blockedAt`.
  - **Device key** (`hub-main.ts`): the Electron parent posts `{ type: 'device-key', pem, deviceId, cloudUrl, appVersion? }` on `process.parentPort` (PKCS#8 PEM, ed25519); the worker starts then. `HUB_CLOUD_URL` / `HUB_DEVICE_ID` (or `hub_meta.device_id`) fill a missing `cloudUrl` / `deviceId`. `HUB_DEVICE_KEY_PEM` is for tests and local runs only - never set it on a till. No key, no worker (the hub still sells). `{ type: 'shutdown' }`, SIGTERM or SIGINT stop the worker, close the app and PGlite, and exit 0.
- **Checks** (#304): `src/hub/sync-worker.spec.ts`: backoff ladder; signer headers verify with the backend's `verifyDeviceSignature` (body, path and query covered), non-ed25519 key refused. `test/hub-sync-worker.e2e-spec.ts` (cloud app on an ephemeral port + Postgres, hub on PGlite in-process, real signed HTTP): first bootstrap; a whole sale drains all `accepted` with bill and tenders equal; a lost ack re-pushed answers `duplicate` with nothing counted twice; a deleted outbox row stops the push at the gap (`seq_gap`, later ops kept, journal still has the lost op, which then drains); a cloud price change reaches the hub menu; `cursor_expired` re-bootstraps with open sales without doubling line modifiers; cloud down -> backoff, offline in `hub_meta`, drains after it comes back; revoked -> locked, PINs cleared, PIN login 401.
- **Status, O1 lock and Sync issues** (#307, H6):
  - `GET /pos/v1/hub/status` (`@AnyStaff`, `src/hub/hub-status.controller.ts`) -> `{ online, lastSyncAt, outboxDepth, mustSyncBefore, locked, lockReason: 'offline_limit'|'revoked'|null, rejections, orphans }`. `mustSyncBefore` = `last_sync_at` + `policy.maxOfflineHours` (the tenant's, from session-status; default 24). `orphans` counts `hub_orphans` when that table exists (#306), else 0.
  - `GET /pos/v1/hub/rejections` and `POST /pos/v1/hub/rejections/:opId/acknowledge` need `settle_bills` (D-7; the web shows Sync issues only on a 200). The list is the unacknowledged `hub_rejections` with `source: 'cloud'` (orphans are counted, not yet listed). Acknowledge marks the row at once (`acknowledged`, `ack_pending`), forwards it to the cloud's `POST /sync/v1/rejections/:opId/acknowledge` when the worker is online, else the next tick sends it (`SyncWorker.forwardAcks`, before the rejections cache refresh, which keeps pending rows); 404 for an unknown op. Route is `local` in the op map; all three are on the allowlist.
  - **Lock** `src/hub/lock.guard.ts` (`HubLockGuard`, `app.useGlobalGuards` in `createHubApp`, so after PosAuthGuard: anonymous still 401): past `mustSyncBefore`, new-sale routes (table order, counter order, line add, combo add) answer 423 `{ error: { code: 'offline_locked', message } }`; finalize, bill, print, other writes and reads carry on (D-8). The next successful pull moves `last_sync_at`, which clears it. `lock_reason = 'revoked'` refuses every write except `/pos/v1/auth/*` with 423 `device_revoked`. The clock comes from `HubContext` (`createHubApp(pg, dataDir, onOp, hub)`), faked in tests.
  - **Desktop port** (`src/hub/desktop-port.ts`, restiq-desktop D3): `hub-main.ts` listens on `process.parentPort` before the store opens and holds an early `device-key` until the worker can start. It posts `{ type: 'status', online, lastSyncAt, outboxDepth, locked, lockReason, lastError, bootstrapped, tenantId, mustSyncBefore }` (ISO dates, same lock computation as the endpoint) after listen, after the worker starts, and after every tick (`SyncWorker` `onTick`).
